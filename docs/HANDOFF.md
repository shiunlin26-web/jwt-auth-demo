# HANDOFF.md：給下一個 AI（或下一個教練）的交接手冊

> 這份是給**接手帶學習者的人或 AI** 看的。`AGENTS.md` 講怎麼在這個 repo 寫程式，這份講**怎麼帶人**：
> 學習者是誰、走到哪、下一步是什麼、一關要長什麼樣子、哪些決定已經定了不要再問。
> 任何 AI 工具都適用，沒有 Claude 專屬的東西。

## 0. 接手的第一個小時

照順序讀，大約一小時：

0. 要在本機跑東西：Windows 用 `scripts\setup.ps1 -SkipTests`、Mac 用 `bash scripts/setup.sh --skip-tests`（`README.md`「每次開機怎麼把專案跑起來」）；先跑 `scripts\doctor.ps1` 或 `bash scripts/doctor.sh`，它會印出這台能做哪幾關。學習者的電腦每次開機都是乾淨的（連 repo 都會消失），他每次都是 clone + 跑這支；帶他做任何需要本機的步驟前先確認他跑過
1. `AGENTS.md`：這個 repo 的規矩（5 分鐘）
2. 這份文件全部（15 分鐘）
2.5. `docs/COACHING.md` 第 1 節（5 分鐘）：**帶做的方法**。學習者 2026-10-20 明確說這種方式理解最快，所有關卡預設這樣帶；第 2 節是走整個專案的排法，要帶哪一關就讀第 3 節對應的腳本
3. `docs/LEARNING.md` 開頭到「路線圖」（10 分鐘），然後**跳著看**關卡 12、13、17 的結構，知道一關長什麼樣（17 最貼近第 3 節的固定格式）
3.5. `docs/ARCHITECTURE.md` 第 1 節（10 分鐘）：四條路徑的圖（請求、部署、事件、觀測），整條鏈一頁看完；第 2 節每一塊「怎麼證明它會動」是哪個 CI job 或網址。交接演練（2026-10-27）證明只讀這一頁就能說出整條鏈
4. `docs/TOUR.md` 第 0 站、第 7 站、第 12 站、第 13 站（20 分鐘）
5. `docs/CHAIN.md`（10 分鐘）：練習專案要走的七環（環 8～11 是選做的基礎設施，練習專案環 7 做過幾個功能再看）

然後做一件事確認你真的懂了：**不看文件，用三句話說出 access token 和 refresh token 各放在哪、為什麼前後端要同站。** 說不出來就回去讀 TOUR.md 第 0 站和 LEARNING.md 關卡 10。

## 1. 學習者是誰

- **背景**：JS/TS 出身，碰過一點 Java，Python 新手（`LEARNING.md` 末尾的「Python 速查」就是為此而寫）。**程度校準（2026-10-20）**：讀 `routes/auth.py` 的 `login` 能正確說出每一步、知道 `await` 在等 I/O、知道 `raise` 之後不執行，所以**程式邏輯看得懂，不用逐行講**；卡住的是後端世界的名詞和看不見的東西（系統表、索引名字從哪來、Neon 的畫面對應程式哪一行、請求在網路上長什麼樣）。帶新內容時先講「這個名詞是什麼、在哪個畫面看得到」，再講邏輯。**2026-10-27 補充**：讀得懂「劇本型」的程式（測試函式、路由函式、一行對一步），讀不懂「準備型」的程式（`conftest.py`、middleware、fixture 這種框架機制），後者明講可以略過、什麼時候回來、怎麼抄。不要自創名詞（曾經用「罐子」講 cookie jar 被問是不是自創），用原文加一句白話。平日的本機是 **Windows VM**（文件裡的 PowerShell 指令、`$env:Path` 都是為此），**沒有 Docker**（VM 裝不了，已確認）；**另有一台 Mac**（晚上與週末用），有 Docker，關卡 21 起需要 Docker 的動手都排在 Mac，Mac 的建置是 `scripts/setup.sh`，`scripts/doctor.*` 會印出這台能做哪幾關。**電腦每次開機都是乾淨系統**：每次都要重裝工具、重拉 repo、重填 `.env`，所以有 `scripts/setup.ps1` 一鍵建置；帶他做任何需要本機的事之前，先確認他跑過這個腳本。
- **目標**：全端。之後要能自己開新專案把前端、後端、登入、部署整條鏈串起來，再擴充功能；概念貫通後換技術棧也能移植。
- **時間**：每天約 4 小時。
- **學習模式**（這是最重要的一條）：**帶著做：一次一個指令，他貼輸出，你從他的輸出講**（方法與每關腳本在 `docs/COACHING.md`）。學習者回饋這種方式理解最快（2026-10-20 定案）。原本的「讀懂 → 跑起來 → 動手改一點」仍然是每關的結構（`LEARNING.md` 的觀念、驗證方式、動手玩、想一想），但**帶的方式**是一步一步帶，不是丟整關給他自己讀。**練的是指揮與驗收，不是打字**；但「讀得懂 log 和關鍵的二十行程式」不能省。
- **語言**：全部中文。程式註解中文，說「為什麼」不說「做什麼」。
- **不要做的事**：不要替學習者做驗收（他要自己照驗收標準檢查）；不要一次丟太多新東西（一關一個主題）；不要用「這很簡單」帶過，要給能親眼看到的證據（Network 分頁、log、測試輸出）。

## 3. 一關要長什麼樣（給 AI 產出新關卡用）

學習者已經習慣這個格式，**不要換**。每一關在 `LEARNING.md` 是一個 `## 關卡 N：標題 ✅` 段落，依序包含：

| 段落 | 內容 | 必要 |
| --- | --- | --- |
| **改動的檔案** | 一行或一個清單，列新增、改寫、刪除的檔案 | 必要 |
| **一句話** | 粗體，這關解決什麼問題、為什麼重要 | 必要 |
| （`PLAIN.md` 加一段） | 情境 / 做了什麼 / 為什麼重要，三到五句，沿用「會員制的店」比喻 | 必要 |
| **觀念** | 先講問題再講解法。能用表格對照的就用表格（「手寫版 vs 套件版」、「以前 vs 現在」） | 必要 |
| **程式怎麼寫** | 貼關鍵的幾行，不貼整個檔案；每段說為什麼 | 必要 |
| **⚠️ 開始前（一次性）** | 要去哪個平台設什麼、要跑什麼指令。只在有外部步驟時寫 | 視情況 |
| **驗證方式** | 編號清單，每一條都是**親眼看得到**的東西：某個分頁、某行 log、某個數字 | 必要 |
| **動手玩** | 3～5 個小改動：改一個數字、註解掉一行，說會壞在哪、為什麼，最後一定寫「改回來」 | 必要 |
| **想一想** | 3～5 個 `<details><summary>Q：…</summary>答案</details>`，先讓他想再展開 | 必要 |

程式面的慣例在 `AGENTS.md`，重點：一關一個 commit、中文訊息、開頭標關卡；註解標 `【關卡 N】`；改了 `models.py` 一定產生遷移；推之前跑 ruff、pytest、lint、build。
關卡做完要一起更新：路線圖表格打勾、`TOUR.md`（如果改到了請求流程或檔案清單）、`README.md` 專案結構（如果新增檔案）。

## 4. 怎麼帶（教練規則）

1. **帶著做，不要丟整關給他讀**。開一關先用 `PLAIN.md` 兩三句講「這關解決什麼」，然後直接照 `docs/COACHING.md` 那關的腳本一步一步帶：一個指令、他貼輸出、從輸出講。`LEARNING.md` 的觀念段落是你的底稿和他的課後複習，不是開場白。收尾後問「哪一步要再講一次」再進下一關。
2. **回答問題時指到檔案和行數**，例如「`client.ts` 第 70 行的 `_retry`」。他會自己去看。
3. **驗收是他的事**。做完一關，列出驗證方式，等他回報結果。他說「過了」就問一個「想一想」確認。
4. **只做被要求的事**。做完列「我注意到但你沒要求、所以我沒做」的清單，只列不做（`AGENTS.md` 規則 1）。
5. **修 bug 先講根本原因**，再改。他要學的是找原因的方法，不是修好的結果。
6. **不確定就問**。尤其是會影響架構的決定（例如 cookie 的 SameSite、要不要加一張表）。
7. **弄壞是設計的一部分**。「動手玩」刻意讓東西壞掉。他回報「壞了」不是求救，先問他「你覺得為什麼」。
8. **每三天一次集中問答**。練習專案期間他會在**練習專案 repo 根目錄**的 `QUESTIONS.md` 累積疑問（`PLAN.md`「練習專案的規則」第 4 條；本 repo 沒有這個檔）。
9. **不要替他寫練習專案**。練習專案的規則是：他下任務（可以直接貼 `CHAIN.md` 的任務描述），AI 做，他驗收。AI 在練習專案裡一樣只做被要求的事。

## 5. 已經定了的事（不要再問）

來自 `PLAN.md`「學習者已做的決定」與後續對話：

1. 每天 4 小時。
2. 只用免費方案：Render、Vercel、Neon、Sentry、GitHub Actions。不買網域。
3. 技術棧固定：FastAPI + SQLModel + Alembic + pytest + uv + ruff + pyright + slowapi；React 19 + Vite + React Router + Zustand + axios + TanStack Query + React Hook Form + Zod + Tailwind + Vitest + MSW + Prettier。**練習專案用同一套**，換棧是 20 天後自己的事。
4. 正式環境**前後端同站**：Vercel rewrites 把 `/api/*` 轉到 Render，cookie 保持 `SameSite=Lax`。不用 `SameSite=None` 硬撐（理由見 `QA.md`）。
5. 遷移在容器啟動時跑（`alembic upgrade head && uvicorn ...`），不用付費的 Pre-Deploy。
6. CI 綠了才部署；main 有 branch protection，一律走 PR。「CI 綠了才部署」是用 Render Dashboard 的 Auto-Deploy: After CI Checks Pass（`ci.yml` 裡沒有 Deploy Hook，所以不是那條備案）。接手時到 Render → Settings → Build & Deploy 看一眼確認。
7. 刻意不碰：Terraform、前端 Dockerfile、自訂網域、線上的 Kubernetes 叢集與託管 Kafka。（slowapi 原本也在這裡，後來做成關卡 17；**Kubernetes 與 docker compose 原本也在這裡，2026-10-22 學習者決定改為做在 `infra/`、只在 CI 和 Mac 上跑、線上不碰**，見 `docs/PLAN-INFRA.md` 第 0 節。）GitHub Codespaces 評估過，學習者偏好本機腳本，不用；有 Mac 之後也不需要。
8. 範例專案凍結。練習專案題目由學習者決定，AI 不要代選（`PLAN.md` 原本寫「待辦含分類」，2026-10-15 改為另行決定，PLAN 本文保留歷史）；他說題目之前，先做跟題目無關的事（開 repo、環 1～6 都不需要題目）。
9. 文件全中文；AI 指引放 `AGENTS.md`，`CLAUDE.md` 只指向它，避免綁定單一工具。
10. **架構與程式碼要是現代開發的專業水準**（2026-10-15 補充）。「這是教學模板」不是降低標準的理由：型別檢查、格式化、lint、測試、CI 全綠才合併，安全細節（例如 bcrypt 不能擋住 event loop、註冊的競態要處理）照正式專案的標準做。教學註解是加在專業程式碼上，不是用來解釋為什麼偷懶。
11. **會碰到付費門檻的事要提早說**（2026-10-15 補充）。部署平台的設定、第三方服務的方案，只要有可能跳出付費頁，動手前先告訴學習者「這一步可能要錢，免費替代方案是＿＿」，讓他決定。已知的邊界：Render 的「After CI Checks Pass」在免費方案不一定有（替代：Deploy Hook）、Render Pre-Deploy Command 要付費（已改用啟動時跑遷移）、Railway 沒有長期免費方案（已排除）、GitHub Actions 私有 repo 每月 2000 分鐘、Neon / Sentry / Vercel Hobby 的額度見 `PLAN.md` 查證表。
12. **帶法是「帶著做」**（2026-10-20）：一次一個指令、他貼輸出、從輸出講，方法與每關腳本在 `docs/COACHING.md`。不要丟整關文件給他讀，不要描述畫面長相。全專案從關卡 0 重新帶一遍，仔細關與快速關的分法在 `COACHING.md` 第 2 節。
13. **GitHub Actions 的分鐘數**（2026-10-22）：repo 已公開，標準 runner 不計分鐘；私有 repo 的分鐘數是整個帳號一池，把這套搬到私有專案時要注意。基礎設施的 job 一律放 `.github/workflows/infra.yml`，只在 PR 與手動觸發、只有 `infra/`、`backend/` 或 E2E 有改動才跑，不放進 `ci.yml`。省分鐘的做法與公開前做過的檢查記在 `docs/PLAN-INFRA.md` 第 7 節。

## 8. 常用的開場提示（複製貼上就能用）

每一段都假設對方是一個沒有任何對話記憶的 AI，而且已經能讀這個 repo。

**接手帶練習專案（題目還沒定，先做環 1～6）：**

> 先讀 jwt-auth-demo 的 `AGENTS.md` 和 `docs/HANDOFF.md`。我是它的學習者，接下來要開一個新的練習專案，照 `docs/CHAIN.md` 的七環走一遍。題目還沒定，環 1～6 跟題目無關，先走。新 repo 的 `AGENTS.md` 用 `CHAIN.md` 附錄 B 的範本。現在從環 1 開始：把 `CHAIN.md` 環 1「給 AI 的任務」整段當成我的任務，技術棧跟 jwt-auth-demo 一樣，列出你要做的事和驗收標準（照環 1 的四條），等我確認再動手。只做被要求的事，做完列出「我注意到但你沒要求、所以我沒做」的清單。commit 由我自己下。

**接手帶練習專案（題目已定，進入環 7）：**

> 先讀 jwt-auth-demo 的 `AGENTS.md` 和 `docs/HANDOFF.md`。練習專案環 1～6 已完成、已上線、CI 綠。題目是：＿＿＿。現在做環 7 的第一個功能：＿＿＿。把 `docs/CHAIN.md` 環 7「給 AI 的任務」套到這個功能上，列出你要做的事和驗收標準，等我確認再動手。只做這個功能，做完列出「我注意到但你沒要求、所以我沒做」的清單。

**接手帶範例專案的延伸主題（路線圖都做完了，從「之後還可以自己摸的」挑）：**

> 先讀 `AGENTS.md` 和 `docs/HANDOFF.md` 第 3 節。請照那個格式帶我做一關：＿＿＿（例如「一個分頁登出，其他分頁立刻跟著登出」，`LEARNING.md` 末尾的表有關鍵字）。先給我「觀念」段落，等我讀完說 OK 再寫程式。一關一個 commit，中文訊息，編號接在路線圖最後一關之後。

**帶我做某一關（範例專案）：**

> 先讀 `AGENTS.md`、`docs/HANDOFF.md`、`docs/COACHING.md` 第 1 節。我是學習者，請照 `docs/COACHING.md` 第 3 節「關卡 N」的腳本帶我做：一次給我一個指令、告訴我預期看到什麼，我貼輸出給你，你從我的輸出講。先確認我前後端有沒有跑起來。不要一次講整關，不要描述畫面長什麼樣，用數字和字串當預期值。收尾後問我哪一步要再講一次。

**壞掉了：**

> 症狀是：＿＿＿（貼 log 或截圖的文字）。先查 `docs/DEBUGGING.md` 有沒有一樣的症狀；沒有的話照它開頭的三個通用動作一步步帶我分段確認，先告訴我根本原因，再提修法。修好之後把這條加進 `DEBUGGING.md`。

**交接演練（每換一個工具或 session 做一次）：**

> 你沒有任何這個專案的記憶。只靠 repo 裡的文件，告訴我：(1) 這個專案是什麼、(2) 我現在走到哪、下一步該做什麼、(3) 如果我要新開一個練習專案，第一個任務該怎麼下。答不出來的地方直接說「文件裡找不到」。

演練之後，把它答不出來或答錯的地方補進對應的文件，這就是文件的洞。

## 9. 已知的限制與沒做的事

- 前端測試（關卡 16）只覆蓋攔截器、守門員、登入表單；端對端測試（Playwright，關卡 21）只走登入主路徑三條，其他頁面靠 Vitest 與手動。
- `LEARNING.md` 已完成的關卡是歷史紀錄：裡面的檔名、指令是當時的版本（例如關卡 6 以前用 `App.tsx`、關卡 9 以前用 `pip`）。開頭和關卡 6 有換算說明，不要回去改寫。
- `PLAN.md` 的 20 天時程已經過期（實際進度比它快），只當設計理由看，不當行事曆。
- 兩個分頁同時重新整理可能觸發 refresh token 的重複使用偵測而雙雙登出（關卡 1 Q2、關卡 6 Q4），刻意沒解，練習專案知道有這回事就好。
- 免費方案的條款會變；`PLAN.md` 的查證是 2026-10-12 的結果。
- 各關卡文件裡的「測試有幾個」是當時的數字（關卡 4 寫 34、關卡 11 寫 39、關卡 13 寫 42、關卡 17 寫 51、關卡 19 寫 52、關卡 24 起 67；前端關卡 16 寫 11），以 `uv run pytest -q`、`npm test` 的輸出為準。

- 這份文件的第 2 節會過期。每次合併 PR、換工具、進度變，都要更新它。
